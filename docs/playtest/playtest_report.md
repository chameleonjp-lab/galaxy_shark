## はじめに：この報告書の読み方

この報告書は、ゲームを「わざと意地悪な目線で」遊び、壊れるところや分かりにくいところを探した結果をまとめたものです。こうした調べ方を、ここでは敵対的検証と呼びます。見つけた問題には、それぞれ「何が起きるか」「どうやって確かめたか」「どう直すとよいか」を書きました。

問題には次の4段階の優先度を付けています。数字が小さいほど急ぎます。

1. **重大**：公開前に直さないと、遊んだ人の多くが困るか、ゲームとして成り立たないもの
2. **高**：多くの人が気づく、または評価を大きく下げるもの
3. **中**：気づく人は気づく、直すと確実に良くなるもの
4. **低**：細かい仕上げ。余裕があれば直したいもの

まずは全体の結論を短く書き、そのあと分野ごとに詳しく説明します。最後に、直したあとで同じ検証をやり直すための道具の使い方を載せました。

## 1. どうやって調べたか

調べ方は大きく4つです。

1つ目は、`index.html` の約7,600行をすべて読み、ルールや数値の決め方を確かめました。2つ目は、自動で遊ぶプログラム（以下「ボット」と呼びます）を作り、時間を早送りしながら最初から最後まで何度も遊ばせました。ボットには「噛みつきを連打する」「必要なときだけ噛む」「一度も噛まない」「何も操作しない」の4種類の遊び方をさせ、結果を比べています。3つ目は、コードを読んで怪しいと思った箇所を、短いテスト用プログラムで1つずつ再現しました。4つ目は、パソコンの横長画面、スマホの縦画面（iPhone 13 相当）、スマホの横画面の3種類で、各フェーズとボス戦の画面写真を撮りました。

ただし、できなかったこともあります。調査はクラウド上の画面のないブラウザで行ったため、本物のスマホでの手ざわりや速さは測れていません。また、音は耳で聞けないので、BGMと効果音はコードの中身から判断しています。こうした点は、本文で「わからない」「推定」と書き分けました。

## 2. 全体の結論

先に、いちばん伝えたいことを書きます。

このゲームは、アメコミ風の見た目、5つのフェーズで舞台ががらりと変わる構成、ボスの攻撃前に「COUNTER! 噛め!!」と教えてくれる表示など、良いところがたくさんあります。とくに、海から銀河まで一気に大きくなっていく流れは、題材としてとても魅力的です。

一方で、検証の結果、**ゲームとしての手応えがほとんどない**ことが分かりました。噛みつきを連打するボットは、ゲーム内時間でわずか **1分38秒** で全5フェーズを突破し、その間に HP は 100 から 94 までしか減りませんでした。5体のボスは、どれも5〜8秒で倒れています。さらに、**噛みつきボタンを一度も押さないボットでも 2分10秒でクリア** できました。チュートリアルで「画面タップで噛みつく!!」と教えているのに、実際は体当たりしているだけで食べられ、ボスまで倒せてしまいます。

加えて、公開前に必ず直したい不具合がいくつか見つかりました。とくに次の3つは、普通に遊んでいても起こりえます。

- 進化メニューを開いている間も敵の攻撃は続くため、そのまま倒されると結果画面と進化メニューが重なります。そこで「もう一度遊ぶ」を押すと、古い進化メニューが残ったままになり、選ぶと進化ポイントがマイナス（-1）になります。
- パソコンでは、キーボードで噛みつく方法がありません。また、マウスを画面の端に置いたままにすると、何も押していなくてもサメが勝手に回り続けます。
- スコアの計算が壊れていて、途中でやられても10万点を超えます。最高ランク「S+」の基準（4万8千点）を大きく上回るので、ランクに意味がなくなっています。

以下、分野ごとに詳しく説明します。

## 4. 重大な問題（公開前に直すべきもの）

### 4-1. ゲームが短すぎて、ほぼ負けない【重大／ゲーム性・難易度】

**何が起きるか。** 上の表のとおり、うまく遊べば2分弱で全クリアでき、その間ほとんどダメージを受けません。ボスはどれも5〜8秒で倒れます。フェーズ5の銀河は、入ってから約5秒でラスボスが出てきます。そのため、恒星群・星雲・他銀河という3種類の獲物を、ほとんど見ないまま終わります。

**なぜそうなるか。** 原因はいくつか重なっています。

まず、ボスは体当たりで一切ダメージを与えてきません（`index.html:6213-6249`）。攻撃は弾だけで、その弾も噛みつき中なら口で消せます（`index.html:6254`）。噛みつきは0.28秒ごとに出せて、0.22秒続くので、連打すると約8割の時間「噛みつき中」になります。つまり、連打している間は弾もほぼ当たりません。

次に、ボスへのダメージは1回あたり最大HPの12%までに抑えられているものの、HPが16%を切ると次の一噛みで必ず倒せます（`index.html:6241`）。強化キバを取っていると、およそ10回噛めば終わる計算です。

さらに、成長がとても速いです。食べるたびに体長が伸びる量はコンボ数に応じて最大2.5倍になり（`index.html:6305`）、しかもコンボは3.5秒以内に次を食べれば途切れません。画面の前方には常に120体以上の獲物が補充されるため、コンボは実質的に途切れず、連打ボットでは最大4,188コンボになりました。

**改善案。** 狙いを「人間が初見で10〜15分、慣れた人で5分前後」と決め、そこから逆算して数値を直すのがよいと思います。具体的には、次のような手が考えられます。

ボスについては、ボスの体に触れるとダメージを受けるようにし、「攻撃のすき（ダウン中）に噛む」という読み合いを作ります。あわせて、HPが16%を切ったら即撃破になる仕組みは「ダウン中に噛んだときだけ」に限定すると、カウンターを狙う意味が生まれます。弾を噛み砕ける判定も、「攻撃予兆のあと0.3秒だけ」のように窓を狭くすると、連打だけでは防げなくなります。

成長については、コンボ倍率の上限を2.5倍から1.5倍程度に下げます。あわせて、コンボの受付時間を食べるたびに少しずつ短くすると、ずっと続けるには腕が必要になります。また、フェーズ5は、ボスが出るまでの体長の基準（`index.html:5783` の `1.2e17`）を上げて、少なくとも30秒ほどは銀河を泳げるようにするとよいでしょう。

### 4-2. 「噛みつき」を押さなくてもクリアできる【重大／ゲーム性・ルールの分かりやすさ】

**何が起きるか。** 噛みつきボタンを一度も押さないボットが、2分10秒でクリアしました。小さい獲物は体が触れるだけで食べられます。大きい獲物とボスも、口が触れているだけで自動的に「GNAW!（かじる）」が発生して削れていきます（`index.html:6182-6210`、`index.html:6225`）。

**なぜ問題か。** チュートリアルは最初に「👆 画面タップでサメが噛みつく!!」と大きく出します。ところが実際は、押しても押さなくても結果があまり変わりません。遊ぶ人は「タップすると何が違うのか」を体で理解できず、操作する楽しさが薄れます。噛みつきはこのゲームの中心となる動きなので、ここが空回りしていると全体の手応えが弱くなります。

**改善案。** 「触れるだけで食べられるのは、自分よりかなり小さい獲物（たとえば体長の40%以下）だけ」に絞ります。それより大きい獲物は、噛みつかないと削れないようにします。そのうえで、ボスへのダメージは噛みつき中のみ入るようにします。さらに、噛みつきが当たったときの効果音・画面の揺れ・ダメージ数字を、体当たりのときより明らかに派手にすると、「押すと強い」が自然に伝わります。

### 4-3. 進化メニューを開いている間に攻撃され、倒れると画面が壊れる【重大／不具合】

**何が起きるか。** 進化メニュー（EVOLUTION SELECT）を開くと、ゲームは止まらず0.15倍の速さで動き続けます（`index.html:6653`）。当たり判定の一部は止まるものの、シャチやライバルザメの突進、クジラの尾ビレの衝撃波など、敵の行動の中にあるダメージ処理は動いたままです（`index.html:7011`、`index.html:7025`）。そのため、メニューを見ている間にダメージを受けます。

テスト用プログラムで再現したところ、進化メニューを開いたまま HP が 100 から 85 に減りました。そのまま HP が0になると、結果画面と進化メニューの両方が同時に表示されました。さらに「もう一度遊ぶ」を押すと、新しいゲームが始まっても古い進化メニューが残ったままでした（`startNewRun` がメニューを閉じていないため。`index.html:5564`）。このときカードを押すと、進化ポイントが0なのに購入でき、ポイントが **-1** になりました。カードを作った時点の「買えるかどうか」を覚えたまま判定しているのが原因です（`index.html:6555`、`index.html:6564-6566`）。

**改善案。** 進化メニューを開いている間は、敵・弾・ボスの動きを完全に止めるのが分かりやすいと思います。スローにする演出を残したいなら、少なくともダメージを受けない状態にします。あわせて、次の2つの守りを入れておくと安心です。

- `showResult()`（結果画面を出す処理）と `startNewRun()`（新しいゲームを始める処理）の中で、進化メニューを必ず閉じる
- カードを押したときに、その場で `evolutionPoints >= ev.cost` をもう一度確かめる

### 4-4. パソコンで、キーボードでは噛めず、マウスでは勝手に曲がる【重大／操作性】

**何が起きるか。** パソコンには2つの困りごとがあります。

1つ目は、キーボードに噛みつきのキーがないことです。スペースキーは、ページが動かないように押しても何も起きない設定になっています（`index.html:5416`）。しかし噛みつきの処理は呼ばれていません。テストでも、スペースキーを押したあとに噛みつき状態になりませんでした。キーボードだけで遊ぼうとすると、移動しながらマウスでクリックする必要があり、手が足りません。

2つ目は、マウスの位置で勝手に舵が切られることです。タッチ操作ができないパソコンでは、キーを何も押していないとき、マウスの位置でサメが曲がります（`index.html:6800-6804`）。これは「マウスがある方へ向く」のではなく、「マウスが画面の右にあるあいだ、右に回り続ける」という動きです。テストでは、マウスを画面の右上に置いたまま何も押さずにいると、2秒で約170度回転し、上へ浮かび続けました。噛みつくためにクリックするとマウスは必ず画面のどこかにあるので、キーから指を離した瞬間にサメが回り出します。陸のフェーズ2では、マウスを画面の上の方に置くだけでジャンプを繰り返します。

さらに、画面にはマウスの位置に照準の丸が出ます（`index.html:7461-7470`）。これでは、遊ぶ人は「そこへ噛みつく」と思ってしまいます。しかし、実際の噛みつきは常にサメの正面へ出ます。

**改善案。** まず、スペースキー（とJキーなど）で噛みつけるようにします。マウス操作については、次のどちらかに決めるとよいでしょう。

- マウスで操作する場合は、「マウスのある方向へサメの向きを合わせる」方式に変える。照準の位置へ噛みつきが飛ぶようにすれば、照準の丸も意味を持つ
- マウスでは操作しない場合は、マウスでの舵取りをやめて、照準の丸も消す

どちらにする場合も、タイトル画面の操作説明に、パソコン用の操作（マウスとキー）を書き足します。

### 4-5. スコアとランクが壊れている【重大／仕様】

**何が起きるか。** スコアは「食べた数×110」と「最大コンボ×260」に、クリア時だけ時間ボーナスを足して計算しています（`index.html:6615-6620`）。ところが、上に書いたとおり、食べた数は数千、コンボも数千になります。通しプレイの記録では、フェーズ1のボス戦の時点で、食べた数もコンボ数もおよそ300に達していました。計算すると、そこでやられても約10万点になります。クリアしたときは、最大で160万点になりました。一方で、ランクの基準は「4万8千点以上でS+」です（`index.html:6625-6628`）。そのため、クリアした人は全員S+になり、ランクを狙う意味がありません。

さらに、やられたときも「10万点」と大きな数字が出るのに、ランクは「TRY AGAIN!」です。これでは、うれしいのか残念なのか分かりにくい画面になります。

**改善案。** スコアの柱を「クリアタイム」「受けたダメージの少なさ」「ボスをカウンターで倒した回数」「金色レアを食べた数」など、腕前が表れるものに変えます。食べた数やコンボは、上限付きのボーナスにとどめます。そのうえで、テスト用ボットの結果を物差しにして、ランクの基準を決め直すとよいでしょう。今回のボットは「最適に近い動き」なので、ボットの点数をS+の少し下に置くのが目安になります。

### 4-6. 画面の部品（Three.js）を読み込めないと、何も起きなくなる【重大／実装・公開】

**何が起きるか。** このゲームは、3D表示のための部品（Three.js r128）を、ネット上の配布元（CDN と呼ばれる仕組み）から毎回読み込んでいます（`index.html:7`）。読み込みに失敗すると、タイトル画面は出るものの、PLAYボタンを押しても何も起きません。テストで読み込みを止めると、`THREE is not defined` というエラーが出て、画面はタイトルのまま固まりました。エラーの理由は画面に表示されません。

学校や会社のネットワーク、広告ブロック、配布元の一時的な障害などで読み込みに失敗することは、珍しくありません。遊ぶ人は「壊れたゲーム」と感じて、そのまま去ってしまいます。

**改善案。** Three.js のファイルをこのリポジトリに入れて、自分のページから読み込む方法が確実です。ライセンスは MIT なので、著作権表示を残せば同梱できます。あわせて、3D表示（WebGL）が使えない端末や読み込み失敗のときに「お使いの環境では表示できません」と表示する処理を入れておくと、遊ぶ人が迷いません。

## 5. 優先度「高」の問題

### 5-1. ボスを無視すると、サメが際限なく大きくなり、次のフェーズを飛ばせる【高／仕様・バランス】

**何が起きるか。** ボスが出ているあいだも、サメは普通の獲物を食べて大きくなり続けます。ステージの番号だけは今のフェーズの中に止められますが、体長には上限がありません（`index.html:5763-5766`、`index.html:6332`）。テストでは、フェーズ1でボスを放っておくと、体長が数kmになりました。そのとき画面には「PHASE 1 海洋 • STAGE 4/15」と「512.0 m」が並びます。

この状態でクラーケンを倒すと、フェーズ2の最初から「STAGE 7」になり、すぐに巨大ロボが出てきます。テストでも、撃破した直後に巨大ロボが出現しました。そのため、フェーズ2の街を味わう時間がまるごと消えます。

**改善案。** ボスが出ているあいだは、体長の伸びを「そのフェーズの最大値」で止めます。たとえばフェーズ1なら50mです。あわせて、普通の獲物の出現数を減らしてボス戦に集中させると、メリハリも生まれます。

### 5-2. フェーズ2で、建物が8割を占め、発電所の連鎖で1秒に100体以上食べる【高／バランス・処理負荷】

**何が起きるか。** フェーズ2では、出現する獲物の78%が、家・高層ビル・ガソリンスタンド・発電所のどれかになります（`index.html:5952-5955`）。この選び方は、ステージごとの出現条件を見ていません。そのため、ステージ5から155mの高層ビルや発電所がたくさん出ます。

さらに、仕掛け付きの獲物（ギミック）は、大きさに関係なく一口で食べられます（`index.html:6117`）。そのうち発電所は、数の制限がありません。ガソリンスタンドなどの爆発系は同時に2つまでですが、発電所はその対象外です（`index.html:1366`）。ダムを壊して街が水没すると、発電所を食べたときに周りの獲物をまとめて飲み込みます（`index.html:6393-6406`）。

テストでは、フェーズ2の5秒間で690体を食べました。1秒あたり約140体です。通しプレイでも、フェーズ2の約15秒で、家・高層ビル・発電所をそれぞれ約600体ずつ食べていました。電車・戦車・市民などは、ほとんど出番がありません。

**なぜ問題か。** 「根元をかじって倒してから食べるのがプロの作法」という高層ビルの紹介文がありますが、実際は勝手に吸い込まれていきます。また、1体食べるごとに効果音（音の部品を10個前後作ります）、粒子の演出、擬音の文字、画面の揺れが出ます。1秒に140体分となると、スマホでは音が割れたり、動きが重くなったりするおそれがあります。ただし、本物のスマホでの重さは測れていないので、どの程度になるかはわかりません。

**改善案。** 街の建物の割合を78%から40%前後に下げ、車・市民・電車・戦車の出番を増やします。発電所も「同時に1つまで」の制限に入れます。水没中の連鎖で食べる数は、1回の感電につき5体まで（ガソリンスタンドと同じ）に抑えます。あわせて、効果音は「同じ種類の音は0.05秒に1回まで」のように間引くと、音の負荷と耳ざわりの両方が良くなります。

### 5-3. 食べるたびに画面が止まり、群れを食べているとカクカクする【高／演出・操作性】

**何が起きるか。** 獲物を1体食べるたびに、画面を0.03秒止める演出が入ります（`index.html:6365`）。当たった瞬間に一瞬止めて手応えを出す、ヒットストップ（hit stop）という手法です。このあいだは、ゲームの時間が進みません（`index.html:6648-6652`）。

1体だけなら気持ちのいい演出です。しかし、このゲームは群れを次々に食べる作りなので、ほぼ毎フレームこの停止が入ります。通しプレイでは、全体のフレームのうち約27%が、この停止に使われていました（1秒に30回画面を書き換える前提で測り、フェーズの合間の物語の場面で止まる時間は除いています）。1秒に60回書き換える端末では、0.03秒の停止が2フレームにまたがるため、止まっている割合はさらに増えると考えられます。遊ぶ人には、映像がカクカクする、あるいはもたつくように見えるはずです。

**改善案。** 小さな獲物ではこの停止を入れず、「自分と同じくらい大きい獲物」「ボスへの一撃」「カウンター成功」だけに使います。さらに、前回の停止から0.2秒以内なら次の停止を入れないようにすると、群れを食べるときの流れが途切れません。

### 5-4. 「もう一度遊ぶ」で、前回の状態が残る【高／不具合】

**何が起きるか。** ゲームをやり直すときの初期化処理（`resetState`、`index.html:5209`）で、戻し忘れている項目があります。テストで確かめたものは次の3つです。

- **BGMが前回のフェーズのまま。** たとえばフェーズ3でやられてやり直すと、海のステージなのに空のフェーズのBGMが流れます（`audio.phase` を戻していないため）。
- **水没の水面が残る。** フェーズ2でダムを壊したあと、水没中にやられてやり直すと、海の中に水色の水面が残ったままになります（`floodPlane.visible` を戻していないため）。
- **最初の進化の説明が毎回出る。** 進化ポイントを初めて得たときに、画面を暗くして「進化」を押すまで先へ進めない説明が出ます。これが、やり直すたびに毎回出ます（`hasCompletedFirstEvo` を毎回 false に戻し、保存もしていないため。`index.html:5269`、`index.html:7548`）。

**改善案。** やり直しのときに、BGMのフェーズと水面の表示を初期値へ戻します。最初の進化の説明は、噛みつきの案内と同じように、ブラウザに「見た」記録を残し（`localStorage` という保存の仕組みを使います）、2回目からは出さないようにします。

### 5-5. 描画の命令が1画面あたり1,200〜2,000回あり、スマホでは重い可能性が高い【高／実装・性能】

**何が起きるか。** 3D描画では、物体ごとに「これを描いて」という命令をグラフィックの部品へ送ります。この命令を描画命令（ドローコール、draw call）と呼びます。数が多いほど重くなります。テストで数えると、1画面あたりの描画命令は、フェーズ1で約1,200回、フェーズ3で約2,000回、フェーズ4で約2,000回でした。

獲物が1体ずつ多くの部品でできていて、そのうえ部品ごとに黒いふち取りの影の部品も付いていることが原因です。描画命令の数の目安は端末によって違いますが、スマホでは数百回程度に抑えるのが一般的とされます。ただし、実機での速さは今回測れていないので、どのくらい重いかはわかりません。

さらに、獲物は後ろへ回るとすぐ消え、前方で1フレームに最大8体ずつ新しく作られます（`index.html:6899-6905`、`index.html:6939-6948`）。作るたびに形と材質を組み立てるため、処理の負担が波のように来て、ときどき引っかかる原因になりえます。

**改善案。** 同じ種類の獲物はまとめて1回の命令で描く仕組み（Three.js の `InstancedMesh`）を使います。あるいは、部品を1つの形に合体させるだけでも、命令の数は大きく減ります。遠くの獲物はふち取りを省くのも有効です。獲物は消して作り直すのではなく、使い回す方式にすると、引っかかりも減ります。

### 5-6. スマホ画面で、表示が重なったりボタンが隠れたりする【高／見た目・操作性】

画面写真で確かめた問題は次のとおりです。

**縦画面のボス戦。** 「VS 巨大ロボ（ボス）!!」の帯と体力バーが、左上の体長・フェーズ表示や「都市水没バフ中」の表示と重なって、どちらも読みにくくなります（`docs/playtest/img/04_boss_hud_overlap_phone_portrait.jpg`）。縦画面では、ボスの表示を画面の上の端いっぱいに置き、左上の表示はボス戦中は小さくまとめると重なりを避けられます。

**横画面の結果画面。** 結果画面の箱の高さが画面の88%までに決められていて、はみ出した分は箱の中で動かして見る作りです（`index.html:945-970`）。横画面では見出し・ランク・スコアだけで高さが埋まります。そのため、「もう一度遊ぶ」「タイトルへ」のボタンが見えません（`docs/playtest/img/05_result_buttons_hidden_phone_landscape.jpg`）。箱の中を指で動かせば出てきますが、それに気づかない人は「先へ進めない」と感じます。横画面では、成績を2列から4列に並べ直すか、ボタンを箱の上の方に固定して表示するとよいでしょう。

**横画面のタイトル。** 左下の操作説明が画面の下で切れて、3行目が見えません（`docs/playtest/img/02_start_overlays_phone_landscape.jpg` の元になったタイトル画面で確認）。

**横画面の開始直後。** 成長ゲージの説明が左のスティックの上に重なり、スティックが半分隠れます（`docs/playtest/img/02_start_overlays_phone_landscape.jpg`）。

### 5-7. 開始直後に案内が3つ同時に出て、しかもゲージの説明がゲージを隠す【高／分かりやすさ】

**何が起きるか。** 初めて遊ぶと、開始直後に次の3つが同時に出ます（`docs/playtest/img/01_start_overlays_desktop.jpg`）。

- 「ISSUE #1: DEEP BLUE HUNGER」の物語の見出し
- 「画面タップでサメが噛みつく!!」の案内
- 「▲ 左上のゲージ＝成長メーター!!」の説明

このうち、ゲージの説明の箱は画面の上から108pxの位置に固定されています（`index.html:393`）。そのため、説明している当のゲージの上に、ちょうど重なって隠してしまいます。また、パソコンでも「画面タップ」と書かれていて、クリックのことだと気づきにくい表現です。

さらに、最初の進化の説明が出るときに、前の2つの案内がまだ消えずに残っていることがあります（`docs/playtest/img/08_forced_evo_with_old_guides.jpg`）。

**改善案。** 案内は1つずつ順番に出します。たとえば「見出し（2秒）→ 噛みつきの案内（実際に1回噛んだら消える）→ 3体食べたらゲージの説明」という流れです。ゲージの説明の箱は、ゲージの真下（今より30〜40px下）へずらします。案内の文章は、パソコンなら「クリック／スペースキー」、スマホなら「タップ」と出し分けます。

## 6. 優先度「中」の問題

### 6-1. 「どれが食べられるか」が見た目では分からない【中／ルールの分かりやすさ】

このゲームでは、自分の体長の68%以下の獲物はそのまま食べられ、それより大きいものは噛んで削る必要があります（`index.html:6106`）。しかし、この境目は画面のどこにも表示されません。「噛んで削れ!」の文字は、近くの大きな獲物1体にしか出ません（`index.html:7398`）。

遊ぶ人は、「なぜこの魚は食べられて、あのカメははね返されたのか」を、遊びながら理解するのが難しい状態です。たとえば始まってすぐのウミガメ（0.85m）は、自分（0.5m）より大きいので噛んで削る必要があります。しかし、見た目は小さなおやつに見えます。

**改善案。** 食べられる獲物には緑の、削る必要がある獲物には黄色の、危ない敵には赤のふち取りを付けるなど、色で見分けられるようにします。このゲームはふち取りの影の部品をすでに持っているので、その色を変えるだけで実現できます。

### 6-2. 成長ゲージの説明と、ボスが出るタイミングが合わない【中／分かりやすさ】

チュートリアルは「ゲージを満タンにするとステージUP＆ボスが出現!!」と説明します。しかし実際のボスは、ゲージが満タンになる前に出ます。計算すると、フェーズ1では約86%、フェーズ2では約75%、フェーズ3では約76%、フェーズ4では約82%で出ます。フェーズ5ではわずか約22%で出ます（`index.html:5778-5784` と `index.html:7512-7516` から計算）。

**改善案。** ボスが出る位置に、ゲージの上で旗やドクロの印を付けます。そうすれば「あそこまで行くとボスが来る」が一目で分かり、説明とのずれも消えます。

### 6-3. 金色のレア獲物が、65秒に1回しか出ない【中／コンテンツ・バランス】

金色のレア獲物は、普段の出現の抽選から外されています（`index.html:5937`）。出てくるのは、65秒ごとの「出現保証」のときだけです（`index.html:6907-6911`）。クリアまで2分弱のゲームなので、1回の通しプレイで1〜2回しか会えません。

また、逃げる速さはサメの大きさに比例して決まります（`index.html:6975`）。そのため、サメが自分の今の単位の中で大きめになると、レア獲物の方が速くなります。計算すると、ステージ1で全速力を出しても、体の大きさの値（内部の倍率）が約2.3を超えると追いつけません。真正面に出たレア獲物を、噛みつきの突進を連打しながらまっすぐ追えば、1〜2秒で捕まえられることはテストで確かめました。ただし、この「突進で追いつく」というコツは、どこにも説明がありません。また、最初に作ったボットは曲がるのが下手だったこともあり、300秒以上追い続けても捕まえられませんでした。しかも、レア獲物は追いかけているあいだは消えないので、追いかけっこが終わりません。

**改善案。** 出現保証の間隔を65秒から30秒前後に縮めます。逃げる速さには「サメの全速力の90%まで」という上限を付けます。あわせて、レア獲物が出たときに「噛みつき突進で追いつけ!」と一言添えると、突進を使う理由が生まれます。

### 6-4. 進化の説明と実際の効果が合っていないものがある【中／仕様】

進化カードの説明と、コードでの実際の効果を照らし合わせると、次のずれがありました。

**「流線ヒレ強化」の旋回。** 説明には「旋回レスポンス向上」とあります。しかし、曲がる速さは水没中かどうかだけで決まっていて、進化の影響を受けません（`index.html:1379`、`index.html:6808`）。

**「破砕クラッシュ顎」の対象。** 説明は「格上・ボスへの噛みつき威力さらに+30%」です。しかし実際は、すべての相手に+30%が付きます（`index.html:1374`、`index.html:5641`）。

**「レーザー・シャーク」の当たり方。** 説明は「前方へ高熱レーザーを発射して削る」です。しかし実際は、正面の少し先の1点の周りにだけダメージが入ります（`index.html:5722-5731`）。そのため、レーザーの線の途中にいる獲物には当たりません。見た目も、ピンクの粒が出るだけで線は描かれません。

**隠し形態の条件と見た目。** 「メカ・シャーク」はコスト0です。そのため、条件を満たすと、進化ポイントが0でも進化ボタンが光り、「⚡ 進化 (0pt)」「進化可能!!」と表示されます。これは「ポイントがないのに進化できる？」と混乱させます。また、「ゴースト・シャーク」の「幽体ステルス装甲」は、実際には被ダメージ40%減と半透明の見た目だけです。敵に見つかりにくくなる効果はありません。

**改善案。** 説明文を実際の効果に合わせるか、効果を説明に合わせます。レーザーは、線上の獲物すべてに当たるようにして、線を描く演出を足すと、説明どおりの気持ちよさになります。隠し形態は、無料で解放できるときはボタンに「隠し形態 解放!!」と別の言葉を出すと迷いません。

### 6-5. もう使われていない機能の言葉が残っている【中／コンテンツ】

かつてあったと思われる「テールスラップ（尻尾ビンタ）」「ドリル突進」「ブースト」は、今は操作する手段がありません。それなのに、次のような文章が残っています。

- 戦闘機の紹介文：「テールスラップで一掃可能。」（`index.html:1341`）
- ニュース：「サメが高速きりもみドリル回転でオフィス街を貫通!!」（`index.html:1420`）

また、獲物ごとに書かれた紹介文（`flavor`。たとえば「すべての伝説はここから始まった。銀色のスナック感覚。」）は、44種類すべてにあります。しかし、画面に出す場所がありません。図鑑の名残と思われるCSSの見出し（`ENCYCLOPEDIA MODAL`）や、使われていない保存用の関数（`loadSavedSet` など）も残っています。

**改善案。** 古い機能の言葉は消すか、今の操作に合う言葉に直します。紹介文はとても楽しい文章なので、捨てるのはもったいないです。「初めて食べた獲物の名前と紹介文を、画面の端に2秒だけ出す」といった形で生かすことを強くおすすめします。図鑑の画面を作り直し、何種類食べたかを集める楽しみにしてもよいでしょう。

### 6-6. 噛みつきを空振りしても「食べた音」が鳴る【中／効果音】

噛みつくと、何にも当たらなくても、食べたときと同じ「ガブッ」という低音と噛み砕く音が鳴ります（`index.html:5691`）。そのため、当たったのか外れたのかを耳で区別できません。

**改善案。** 空振りのときは、軽く「カチッ」と歯が鳴る短い音にします。当たったときだけ、今の重い音を鳴らします。

### 6-7. ボスの名前が「VS クラーケン（ボス）!!」になる【中／見た目】

ボスの登場の帯と体力バーの名前に、データ上の名前がそのまま使われています（`index.html:6084-6086`）。そのため、「VS クラーケン（ボス）!!」「VS 巨大ロボ（ボス）!!」のように、説明用の「（ボス）」まで表示されます。

**改善案。** 画面に出すための名前を別に用意し、「VS クラーケン!!」のように表示します。

### 6-8. 大きな数の表示がくずれる【中／見た目】

体長・質量・被害総額を読みやすくする処理に、途中の単位が抜けています（`index.html:1464-1492`）。テストで結果画面に出したところ、次のようになりました。

- 総捕食質量が「6000000000.00 兆t」（本来は「60.00 垓t」のような表示が自然）
- 体長が「500000.00 万km」（「億km」の単位がないため）
- 被害総額が「30.00 秭円」（秭の上の単位がない。今回の通しプレイの範囲では垓円までで収まりました）

フェーズ4の途中でやられると、質量がこの「6000000000.00 兆t」のような表示になる可能性があります。

**改善案。** 万・億・兆・京・垓・秭の単位を順に使う処理にまとめ、3桁ごとのカンマも入れます。

### 6-9. 擬音の文字が画面をおおって、前が見えなくなる【中／演出】

フェーズ3とフェーズ4では、食べるたびに大きな擬音の文字（「CHOP!」「CRISP!」など）が出ます。群れをまとめて食べると、それが画面の下半分を埋めつくします（`docs/playtest/img/06_onomatopoeia_flood_phase3.jpg`）。擬音の文字はほかの物体より手前に描かれる設定なので（`depthTest: false`）、サメも獲物も隠れます。

**改善案。** 同時に出す擬音は最大4つ程度にし、それ以上は出さないか、小さくします。小さな獲物では擬音を出さず、大きな獲物やコンボの節目（10、50、100コンボなど）だけに出すと、ひとつひとつの擬音が際立ちます。

### 6-10. 巨大ロボの頭が画面の外に切れる【中／見た目】

フェーズ2の巨大ロボは、カメラが低いため、体が建物に隠れ、頭だけが画面の上の端に見えます（`docs/playtest/img/07_robo_boss_cut_off.jpg`）。せっかくの「VS 巨大ロボ」の場面なのに、相手の全身が見えません。

**改善案。** ボス戦のあいだだけ、カメラを少し引いて上から見下ろす角度にします。あるいは、登場の瞬間に、ボスの全身を映す短いカメラの動きを入れます。

### 6-11. 曲がると、すぐ後ろの獲物が消える【中／仕様】

獲物は、サメの少し後ろへ回った時点で、すぐに消されます（`index.html:6939-6948`）。そのため、大きな獲物を半分まで削ったあとで回り込もうとすると、削った獲物ごと消えてしまいます。攻撃してくる敵も、後ろへ回ると消えます。

**改善案。** 削り途中の獲物と、攻撃態勢に入った敵は、後ろへ回っても消さないようにします。

### 6-12. 体の大きさの表示が途中で止まる区間がある【中／見た目】

フェーズ4の後半では、大きさの単位の切り替えが150万mの次は1億5千万mになっています（`index.html:1249-1250`）。この幅は100倍もあります。いっぽう、内部の大きさの値には18倍の上限があります（`index.html:5804`）。そのため、体長がおよそ2,700万mから1億5千万mまでのあいだ、サメの見た目の大きさとカメラの距離が止まります。数字は増えているのに、画面上では大きくなっていないように見えます。

**改善案。** 単位の切り替えの間を、1,500万mのところにもう1段入れて、10倍ずつにそろえます。

### 6-13. ステージアップ時のニュースが、今の状況と合わない【中／コンテンツ】

ステージが上がると、ステージ番号をもとにニュースが選ばれます（`index.html:5773-5774`）。そのため、内容と状況がずれます。たとえば体長1.5mのときに「体長5m超の巨大サメが出現」と流れます。また、フェーズ2に入った直後には、まだ何も爆発していないのに「ガソリンスタンドが連鎖大爆発」と流れることがあります。

**改善案。** ニュースは「その出来事が起きたとき」に流す形に寄せます。たとえば、初めてガソリンスタンドを食べたら爆発のニュースを流します。

## 7. 優先度「低」の問題（仕上げ）

### 7-1. 設定や言葉づかいの細かい点【低／分かりやすさ】

設定まわりと言葉づかいには、細かい引っかかりがいくつかあります。

まず、設定が保存されません。スキン、音のオン・オフ、スティックの表示、24FPS、点滅軽減は、ページを開き直すとすべて元に戻ります。次に、タイトルの音のボタンは「SFX: ON」（効果音の意味）と書かれていますが、実際はBGMも一緒に消えます。また、スマホでも「再開する (ESC)」「あとで選ぶ (ESC)」とキーボードのキーが書かれています。

操作説明も、実際の動きとずれています。説明の「WASD：前後左右移動」は、実際は A と D が「横へ移動」ではなく「向きを変える」です。また、矢印キーは「←→で向きを変え、↑↓で上下」と、WASDとは役割が違うのに、その説明がありません。R・C キーでの上下移動や、V キーで進化メニューを開けることも書かれていません。

結果画面にも、言葉の引っかかりがあります。ボタンの「もう一度遊ぶ (RTA)」の RTA（できるだけ速くクリアを目指す遊び方）は、知らない人には意味が通じにくい言葉です。また、やられたときの結果画面にも「クリアタイム」と表示されます。

最後に、メニューで「STICK: ON」にすると、パソコンではマウス操作が止まる仕組みになっています（`index.html:6800`）。この関係は分かりにくいと思います。

**改善案。** 設定は `localStorage` に保存します。音は「BGM」と「効果音」を分けるか、ボタンを「音: ON」にします。キーの表記は、タッチ端末では出さないようにします。

### 7-2. 体にやさしい表示への配慮【低／見た目】

「点滅軽減」は、ボス撃破時などの白い閃光だけに効きます。攻撃予告の「⚡ ATTACK!!」の文字は、1秒に5回の速さで赤と黄色が入れ替わり、点滅します（`index.html:7413`）。画面の揺れを止める設定もありません。乗り物酔いしやすい人や光に敏感な人に向けて、次の対応を検討してください。

- 「画面の揺れ: 弱/切」の設定を足す
- 点滅軽減を ON にしたときは、文字の点滅も止める
- 端末の「視差効果を減らす」設定（`prefers-reduced-motion`）を読み取り、最初から揺れと点滅を弱める

### 7-3. 公開まわりの準備【低／公開】

公開の準備として、次の点が気になりました。

- ページの説明文（`meta description`）、SNSで共有したときの画像と説明（OGP）、ブラウザのタブに出る小さなアイコン（favicon）がありません。共有されたときの見え方に影響します。
- ライセンスの表記と、Three.js（MIT ライセンス）の著作権表示がありません。Three.js を同梱する場合（4-6の改善案）は、表示が必須になります。
- 画面の拡大を禁止しています（`user-scalable=no`）。ゲームとしてはよくある設定ですが、結果画面などの文字を拡大して読みたい人は困ります。

### 7-4. 内容の表現について【低／コンテンツ】

「市民 / 警官」を食べる、実在の「東京湾」「総理」「自衛隊」「海上保安庁」「ISS」が登場する、といった表現があります。コミカルな描き方なので、問題になる可能性は高くないと考えます。ただし、公開する場所（ゲーム投稿サイトやストア）によっては、年齢区分や表現の基準に照らして確認を求められることがあります。基準はサイトごとに違うので、公開先の規約を一度確認しておくと安心です。

### 7-5. そのほかの細かい点【低】

ここまでに入らなかった細かい点を、まとめて書きます。

画面と見た目について。縦画面のタイトルでは、ロゴ「GALAXY SHARK」がほぼ黒く見えて読みにくくなっていました（`docs/playtest/img/03_title_phone_portrait.jpg`）。文字が小さくなっても黒いふち取りの太さが4pxのまま変わらず、中の色を塗りつぶしてしまうのが原因と考えられます（`index.html:764-773`）。また、「ISSUE #1 • 0.5m → 100,000 LY」の札が、縦画面で「LY」だけ次の行に落ちます。さらに、ゲームの上に重ねて描いている2Dの演出（集中線や体力バー）は、画面の細かさ（解像度）を考慮していません（`index.html:7575`）。そのため、高精細な画面では少しぼやけます。

端末の判定について。スマホかどうかを、端末の名前と画面の横幅（1024px未満か）で判定しています（`index.html:1246`）。最近の iPad のブラウザは自分をパソコンとして名乗るため、横向きの iPad はパソコンと同じ重い設定（粒子の数が多い、ふちのギザギザを消す処理あり）で動く可能性があります。実機では確かめていません。

音について。BGMは、フェーズごとに2小節ほどの短い繰り返しです（`index.html:1791-1853`）。ボス戦専用の曲もなく、手配度（★の数）を音に反映する仕組みも、準備だけされていて使われていません。耳で聞いての評価はできていないので、聞いた印象がどうかはわかりません。ただ、ボス戦に入ったときに速さや音色を変えるだけでも、場面の切り替わりがはっきりすると思います。

## 8. 良かったところ（残してほしい点）

厳しい指摘が多くなったので、良かった点もはっきり書いておきます。

見た目の方向性は、とても強い個性があります。網点（アメコミの印刷のような点々）とふち取りの陰影、フェーズごとに一変する空と地面の色、ページを破る開始演出などは、短い時間でも印象に残ります。ボスの作り込みも見事です。クラーケンの8本の脚、巨大ロボの胸部コア、太陽のプロミネンス、天の川銀河の渦巻きなど、それぞれに専用の形と動きがあります。

遊びの仕組みでは、敵が攻撃する前に「⚡ ATTACK!!」を出し、噛み返せる瞬間に「⚡ COUNTER! 噛め!!」へ切り替える表示が、とても良い設計です。「なぜやられたか」「どうすれば防げたか」が、遊びながら分かるようになっています。この仕組みは、4-1と4-2の改善で噛みつきに意味を持たせると、さらに生きてきます。

ほかにも、ニュースの見出しが流れる演出、フェーズの合間の物語のコマ、ゲームの途中でタブを切り替えると自動で一時停止する配慮など、遊ぶ人を楽しませる工夫が随所にあります。

## 10. 検証をやり直すための道具

今回使ったテスト用プログラムを、`docs/playtest/tools/` に入れました。直したあとに同じ検証を走らせ、数字が変わったかを確かめるのに使えます。準備と使い方は次のとおりです。

```bash
# 準備（1回だけ）: Three.js r128 を npm から取得し、Playwright を用意する
npm pack three@0.128.0 && tar -xzf three-0.128.0.tgz
export THREE_PATH=$PWD/package/build/three.min.js
npm install playwright   # すでにある環境では不要

# 通しプレイ（遊び方: spam=連打 / smart=近いときだけ噛む / nobite=噛まない / idle=何もしない）
node docs/playtest/tools/bot.js spam 1500
node docs/playtest/tools/bot.js nobite 900 DESTROYER,MUTANT,SWIFT 2

# 個別の不具合の再現（進化メニュー中の被弾、やり直し時の持ち越し、数値表示など）
node docs/playtest/tools/bugs.js
node docs/playtest/tools/bugs2.js

# 描画命令の数と、Three.js を読み込めないときの動き
node docs/playtest/tools/perf.js
```

`bot.js` は、時間を早送りするために、ブラウザの時計と描画の呼び出しを差し替えて動かします。そのため、本物の端末での速さとは違う点に注意してください。数字は「ゲームの中で何秒かかったか」を表します。
